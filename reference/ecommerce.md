# eCommerce demo module

The operations dashboard is `/dashboards/ecommerce`. Workspace routes under `/apps/ecommerce` are `products`, `products/new`, `products/[id]`, `categories`, `orders`, `orders/[id]`, `inventory`, `customers`, `coupons`, `reviews` and `refunds`. Sidebar links and header search use the existing navigation configuration.

The dashboard uses an asymmetrical revenue/fulfilment composition with a reference-style summary row for Total products, Total revenue, Total orders and Customers. Its store/date filters update revenue, comparison buckets, order counts, product/category sales, customer insights and refund queues. Inventory is store-scoped, not date-scoped; review moderation notifications explicitly cover all stores. The fixed demo date is November 1, 2026, so screenshots and coupon status remain reproducible.

The summary cards reuse the shared MetricCard’s optional inset variant; existing Sales cards retain their default rendering. Product count is the current catalog total versus its count at the start of the selected period. The other summaries compare equal-length order periods; Customers counts distinct customers with orders. The menu on each summary links to its related records and exports its metric with the comparison definition. Percentages are calculated from demo data rather than copied from the visual reference.

The dashboard now contains twelve distinct widgets: an interactive revenue/orders explorer, selectable fulfilment stages, ranked product sales, clickable category composition, buyer segmentation and spenders, order-value distribution, basket size and frequently paired products, revenue reconciliation, recent orders, stock-cover/replenishment priorities, refund queue and operations action center. These use the existing typed orders and inventory; no fabricated conversion, acquisition, profit or carrier metrics are introduced. Stock cover is a historical run-rate estimate. The reconciliation shows subtotal minus discounts plus shipping/tax minus completed refunds, matching net collected revenue.

Shared AppShell, Header, Sidebar, Footer, PageHeader, Card, ChartCard, ChartTooltip, Button, Input, Select, Badge, DataTable, EmptyState and Dialog are reused. All new feature styling uses Tailwind utilities and existing theme variables. No global tokens or Sales/CRM feature code were changed.

All eCommerce card headings use CommerceCardTitle: a centralized label/icon mapping with 14px decorative Lucide icons. CommerceWorkspace applies uppercase 11px/500 headings, a 6px icon gap, 28px minimum header height, 8px header spacing and compact header selects. These rules are scoped to eCommerce; Sales, CRM and shared global card styles retain their existing appearance.

## Local interactions

- Products: searchable/sortable/paginated table, searchable/sorted/paginated grid, category/stock/status filters; create/edit validated records; up to four bundled or locally uploaded PNG/JPEG/WebP photos (400 KB each). Product details include a thumbnail gallery with enlargement and keyboard navigation, SKU copying, pricing comparisons, catalog readiness, period-filtered item performance, and orders/reviews/inventory-history tabs. Item revenue is before tax, shipping and order discounts; partial order refunds are not allocated to products. Inventory and reviews show all dates with explicit labels. Summary export follows the selected sales period.
- Categories: create/edit unique names and descriptions with live product counts.
- Orders: overview of order counts, net collections, unpaid balances and dispatch priorities; queue tabs; combined store/date/payment/fulfilment filters; searchable/sortable/paginated register with product thumbnails and tracking references; quick previews; row selection and CSV exports of all matching or selected orders. Exports follow the active filters and search. Full details retain item/customer/payment details, shipping timeline, validated forward status transitions, simulated payment and required tracking for dispatch. Overview totals follow store/date/payment scope, while tabs and search refine the register.
  Order details use a compact order snapshot, historical line prices with product photos, a five-stage shipping indicator, expandable dated events, tracking-reference copying, customer/address context and a payment/refund ledger. A separate fulfilment panel preserves transition/payment/tracking validation. Order CSV export and clipboard actions are local; no carrier, payment processor or customer is contacted.
- Inventory: low-stock filter, signed stock adjustments with nonnegative stock validation and movement ledger. The ledger tracks local adjustments; seeded stock is an opening snapshot, not a real warehouse reconciliation. Changing an order stage does not make a second stock deduction.
- Customers: profiles, purchase history and net collected totals after completed partial refunds.
- Coupons: create/edit, unique codes, percentage/fixed discounts, expiry and usage limits. No checkout exists; coupons do not retroactively change orders.
- Reviews: rating distribution, status filter, publish/hide moderation.
- Refunds: requested/approved/rejected/completed lifecycle; payment/remaining-amount guards. Partial refunds reduce revenue; completing a full refund also marks the order refunded/returned. No processor is contacted.

Typed seed data lives in `src/features/ecommerce/seed.ts`; domain types and selectors are shared. `demo-service.ts` persists to `nova-ecommerce-demo-v1`, validates stored records and references, listens for cross-tab storage changes, and falls back to seed data with a visible warning for invalid data. Storage quota/access errors leave changes in memory with a warning. Remove that key in browser developer tools to reset this module. Local data is unauthenticated demo data and must not contain sensitive information. Missing-record and empty search states are implemented.

## Verification

Run `npm run typecheck`, `npm run lint`, `npm run build` and `node scripts/verify-ecommerce.mjs`. Set `VISUAL_BASE_URL` to a running production preview URL to test the production build. The browser script uses installed Chrome, checks the main workflows and persistence, and visits all twelve route variants at 1440, 768, 390 and 320 pixels in light/dark themes, with modal centering/Escape, missing-record and corrupt-storage checks. Dashboard captures are written to `artifacts/ecommerce/`.

Generated catalog images and their exact prompts are documented in [ecommerce-image-prompts.md](ecommerce-image-prompts.md). Products, stores, customers, payments and carrier references are fictional. No backend, authentication, checkout, payment processing, email or shipping integration is provided.
